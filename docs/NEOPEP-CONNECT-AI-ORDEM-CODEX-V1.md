## 1. Resultado de produto
O usuário cria conteúdo no próprio chat ChatGPT, Claude ou Gemini; o NeoPep Connect AI é o conector que lê e opera Campanhas. Não criar chat próprio nem exigir chave de IA para ações de campanhas. Um backend e catálogo compartilhados; adaptadores finos específicos dos hosts quando necessários. Plugin privado inicialmente, múltiplas contas da mesma IA, App e WhatsApp, novas e antigas campanhas. Operações idempotentes, edição e auditoria. Gerar e transferir criativos onde o host realmente suporta isso; fallback de arquivo e opcional geração de imagem via API existente apenas com autorização de custo. Nenhuma promessa de suporte quando plano, região ou cliente não permitem.

## 4. Etapas de implementação e gates
001 (planejada) — Consolidar inventário de todos os fluxos reais, mapear payloads/retornos, regras, status, limites e ownership; matriz de diferença Teste/Produção, legado/estruturado. Registrar tabela operação -> RPC -> payload -> permissões -> teste -> documentação. Identificar lacunas, sem declarar paridade não testada.
002 — Catálogo declarativo versionado de ferramentas e schemas JSON (input/output, exemplos, scopes, readOnly/destructive/idempotent, prerequisites, errors). Usar catálogo como fonte para MCP tools/list, documentação gerada e testes. Definir compatibilidade e versão por ambiente. Inicialmente somente get_capabilities, get_brand_context, list_campaigns, get_campaign, get_schedule_status, com dados sintéticos e mocks. Paginação e retorno mínimo.
003 — Autenticação: estudar OAuth 2.1 PKCE, descoberta e protected resource metadata; validar opção Supabase OAuth beta sem habilitar globalmente em produção. Provar vinculação de autorização real à sessão NeoPep e RPC sob identidade correta; sem forjar JWT ou burlar auth.uid/issuer via service_role. Se necessário, propor adaptadores escopados com as mesmas regras e testes. Registro individual de client/conexão, nome customizado, ambiente, scopes, consentimento, expiração, renovação, last_used, revogação e auditoria; várias contas do mesmo host. Pareamento por código de uso único com expiração e confirmação autenticada somente se host suportar, nunca token em chat. Sem privilégios além da Central; revalidar admin e owner em cada operação, isolamento entre contas e ambientes, rate limits e anti-replay.
004 — Serviço MCP privado com SDK oficial e Streamable HTTP, sem ferramentas arbitrárias (SQL, shell, RPC genérica). Teste handshake, tools/list, tools/call, falhas de auth, schemas. Adaptador ChatGPT Sites se elegível para Plus; Claude remoto; Gemini condicionado a região/plano. Não tornar integração pública. Homologar com contas reais só após autorização e acesso.
005 — Menu Campanhas > Integrações com IA, independente de App/WhatsApp. Conexões e permissões, instruções de instalação e links, escolher ambiente, revogar, identidade visual, base de conhecimento versionada, ferramentas, campanhas recebidas e existentes, logs/status e diagnóstico. UI responsiva iPhone/PWA/Windows, tema claro/escuro, estados indisponível/pending sem simular conexão.
006 — Escrita de rascunhos: create_campaign_draft, add_publications, update_publications; usar UUIDs/request_id estáveis, revisão esperada, validar dados, conteúdo editorial e formato por canal. Testar duas publicações sintéticas por canal; repetir mesma requisição e verificar não duplicar. Consultar/editar campanhas existentes com ownership; operações legadas nativas somente, não adotar/migrar automaticamente.
007 — Criativos: attach_creatives, create_upload_ticket, status de mídia. Adaptador ChatGPT de file inputs conforme docs atuais; prova de arquivo gerado no chat, seleção fallback. Claude/Gemini capacidades reais, fallback de anexos/upload. Não aceitar URL externa arbitrária; autorizar origem, evitar SSRF/DNS rebinding/redirect privado, conferir tamanho, bytes/mime, reencode seguro e privado; usar JPEG <=1 MiB e limites nativos de PDF/MP4 <=5 MiB quando autorizados, limites verificados no backend. Mapear mídia por publication_id/block_id, recibo por item, evitar arquivo órfão ou vínculo trocado; retries idempotentes. Não usar fotos/dados de membros, inventar prova social ou gerar promoção de medicamentos controlados/experimentais. Opcional API de imagem com orçamento separado, não padrão.

## 5. Matriz de aceite obrigatória
- Auth: anônimo, usuário comum, outro owner, token expirado/revogado, scope insuficiente, troca de conta/ambiente, código reutilizado, múltiplas conexões independentes; nenhuma fuga de segredo.
- Leitura: listar App/WA existentes, paginar, identificar legado, status real e histórico sem mutação.
- Criação: campanha + dois posts por canal; repetir request ID, revisão conflitante, título/data inválida, falha parcial, recuperar sem duplicar; não publicar rascunho.
- Mídia: upload de arquivo sintético, PNG/JPEG válido, MIME falso, excesso de tamanho, URL localhost/privada/redirect, ID de outra conta, troca de associação; prévia correta; imagem gerada transferida no host real ou fallback declarado.
- Destinos/agenda: grupo desconectado e troca de WhatsApp, público App/push, datas passadas, fuso, revisão alterada após prévia, nonce vencido/reutilizado, cancelar e reprogramar, idempotência; zero envios reais em teste não autorizado.
- Recorrência: limites reais, datas inválidas, pausa/cancelamento e histórico preservado; cópia entre canais sem disparar.
- Docs: alterar schema sem regenerar, contrato desatualizado deve falhar; manter versões Prod/Teste separadas; teste de exemplo inválido.
- UI: iPhone/Windows, claro/escuro, estado conectado/revogado, acessibilidade e navegação sem perder rascunhos.
- Infra: domínio não existente/host indisponível, quota de deploy, TLS/HTTPS, timeout, logs saneados; plano de reversão sem alterações de dados ou publicação indevida.
- Hosts: provar instalação e leitura/escrita com confirmação onde disponível, sem usar APIs internas do NeoPep para gerar textos por padrão. Não afirmar que Gemini Brasil ou ChatGPT Plus aceita escrita antes de prova.
