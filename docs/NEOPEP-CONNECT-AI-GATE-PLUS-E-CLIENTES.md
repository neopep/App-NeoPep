# NeoPep Connect AI — gate de instalação privada e clientes (26/11/2026)

Usuário confirmou ChatGPT Plus como conta-alvo. Free/Go não são prioridades de homologação. ChatGPT, Claude e Gemini continuam alvos obrigatórios; Codex é adicional. Distribuição privada, sem submissão pública. Este documento complementa INSTALACAO, COMPATIBILIDADE-CLIENTES e ORDEM-CODEX-V1; não interromper trabalho concorrente. Reconciliar HEAD remoto antes de push, sem force push.

## Evidência oficial e limites
- Plus: Sites está disponível; criação/edição usa limite Codex. Free/Go não têm Sites conforme artigo específico de disponibilidade. O artigo genérico de plugins menciona criação via Sites em qualquer plano, condicionada ao acesso; não presumir disponibilidade Free. Sites deve ser alternativa opcional para Plus Web, com prova de ligação autenticada ao Cloudflare e sem duplicar lógica de negócio. Publicar Site para criar seu plugin privado não equivale a submissão pública; contas pessoais não podem compartilhar diretamente plugin hospedado em Site por link/convite. Testar iPhone separadamente.
- OpenAI: catálogo local em Work/Codex Desktop é documentado; instalação do pacote e registro/execução de MCP remoto são gates distintos. O fluxo oficial de plugin-creator com MCP registrado pede ID plugin_asdk_app e mapping apps; a criação direta do MCP remoto completo no Web é Business/Enterprise/Edu. Não afirmar que ZIP ou marketplace contorna isso no Plus. Provar no Plus Desktop o pacote portátil mcp.json remoto, sem depender de cadastro inelegível; validar fallback compatível e, se bloqueado, usar Sites como alternativa oficial. Não instalar runtime local de processamento, nem exigir computador ligado para o backend. Free não é alvo, mas não afirmar impossibilidade universal de plugins Free.
- Claude Free: um conector remoto; Pro e demais elegíveis também. Sem file transfers nativo em conectores personalizados, conforme Anthropic; preparar fallback upload seguro. Gemini custom apps: documentação atual exige EUA, inglês, conta Google pessoal adulta, histórico ativo; conexão criada no Web, uso móvel condicionado. Bloqueio de região não será resolvido por código NeoPep; manter protocolo e registrar indisponibilidade Brasil sem contornar.

## Gate técnico antes de instalar
1. OAuth: revisar opção de provedor estabelecido vs emissor próprio, documentar decisão. O código atual usa Map de clientes predefinidos, escopo único read, discovery e token endpoint parciais. Completar HTTP authorize/consent (state, CSRF, redirect exato, PKCE S256, sessão real), JWKS pública com rotação e chaves privadas em secrets, audience/resource e issuer, RFC 9207 iss em retornos se anunciado, escolha de CIMD/DCR ou clientes predefinidos compatíveis com cada host. Não anunciar métodos não implementados. Se CIMD/DCR, validação rigorosa dos metadados e redirect, limites e proteção SSRF; não aceitar clientes/redirects arbitrários. Revisar escopos e client_id conforme comprimentos reais e política, autenticação do token endpoint, rate limits, revogação e rotação, testes de replay/concorrência/expiração. Broker de sessão NeoPep com identidade do titular, sem service_role para operações nativas; credenciais do emissor de privilégio mínimo, refresh seguro, nenhuma chave no ZIP. Não exigir token manual no chat.
2. Worker: entrada padrão permanece fechada; preparar wiring real por ambiente, rotas OAuth/metadata/JWKS, runtime Cloudflare local e teste SDK oficial, limites CPU/memória e chamadas, diagnóstico sem secrets. Confirmar Workers plan e custo antes de ativação. Preparar deploy/rollback isolado de Teste, DNS/domínio, grants e SQL revisados; aplicar só mediante autorização. Não alterar Vercel/Windows/Mercado Pago/agentes.
3. Pacotes: verificar schemas oficiais reais (403 anterior não é validação), manifestos e catálogo, instalação com @plugin-creator quando elegível, configuração MCP do Codex, checksums e atualização com cache/versionamento. Materializar árvore do marketplace em pacote dedicado sem clonar repositório administrativo inteiro. Não vender ZIP como instalação 1-clique; só habilitar download/verificação após prova real. Disponibilizar guia específico Plus Desktop, Plus Web Sites, iPhone, Claude, Gemini, Codex na seção Instalar integração; mostrar planos, região, versão, limitações e status verdadeiros. Nunca expor segredo ou dados de membros.
4. Criativos: ChatGPT file input _meta[openai/fileParams] conforme referência; testar imagem recém-gerada/anexada com cliente real. Claude não oferece transferência nativa em custom connector; URL de upload curta autorizada e vinculada a publicação/bloco, sem acesso a URL arbitrária. Mesmo fallback para demais hosts. Validar MIME/bytes/tamanho, associação, armazenamento privado, expiração, SSRF, custo e limites; não usar API paga de geração por padrão.
5. Homologação: começar com MCP Teste somente leitura e dados sintéticos autorizados; conectar duas contas independentes, testar descoberta e revogação de uma, leitura App/WA, refresh, desconexão e reconexão. Depois rascunho e mídia, confirmação verificável para agenda/publicação; sem disparo real não autorizado. Testar Plus Desktop/Work, Web e iPhone separadamente; se bloqueado documentar tela/erro e alternativa. Sem prometer sincronização. Manter os 14 módulos em desenvolvimento, sem bloquear partes independentes por limitação de plataforma.
